# 서버리스 퀴즈 플랫폼 — 요구사항 명세서

## 1. 개요

실시간 참여형 퀴즈 플랫폼. 퀴즈 관리자가 문제를 출제하고, 참여자들이 제한시간 내 응답하며, 문제별/최종 리더보드와 상품 추첨을 제공한다. AWS 서버리스 아키텍처로 비용 최적화하며, 수십 명 규모의 동시 접속을 지원한다.

### 1.1 기술 스택 (확정)

| 영역 | 선택 |
|------|------|
| 프론트엔드 | React (SPA) |
| 정적 호스팅 | CloudFront + S3 |
| REST API | API Gateway (HTTP API) + Lambda |
| 실시간 통신 | API Gateway (WebSocket API) + Lambda |
| 데이터 저장 | DynamoDB (TTL 기반 자동 만료) |
| 이미지 저장 | S3 (presigned URL 업로드) |
| IaC | AWS SAM |
| 인증 | 닉네임 기반 (별도 로그인 없음) |
| 예상 규모 | 세션당 동시 접속 수십 명 |
| 인쇄 | 브라우저 인쇄 (`window.print()`, CSS `@media print`) |

## 2. 역할 (Actor)

| 역할 | 설명 | 인증 방식 |
|------|------|-----------|
| 마스터 관리자 (Master) | 퀴즈 Code를 발급하고 만료일을 지정. 플랫폼 운영자. | 사전 공유 비밀키/마스터 토큰 |
| 퀴즈 관리자 (Host) | 발급받은 Code로 퀴즈를 세팅·진행. | 퀴즈 Code + 관리자 PIN |
| 참여자 (Player) | 공유된 참여 Code로 입장, 닉네임 입력 후 응답. | 닉네임 + 참여 Code |

> 참여자는 별도 계정이 없다. 닉네임은 세션 내에서만 유효하며 WebSocket 연결과 매핑된다.

## 3. 기능 요구사항

### 3.1 마스터 관리자

| ID | 기능 | 상세 |
|----|------|------|
| M-1 | 퀴즈 발행 + 링크 전달 | 신규 퀴즈 세션용 고유 Code 생성, 관리자 PIN 발급. **참여자 공유 링크**와 **호스트 접속 링크**를 생성해 전달. 호스트에게는 URL + PIN을 마스터가 전달(**PIN은 링크에 미포함**). |
| M-2 | 만료일 지정 | 퀴즈 사용 예정일 기준 만료 시각(epoch) 지정. 이 시각 이후 관련 데이터 자동 삭제. |
| M-3 | 발급 목록 조회 | 발급한 Code 상태(미사용/진행/종료/만료) + 링크 확인. |
| M-4 | 퀴즈 삭제 | 해당 Code의 **모든 데이터 완전 삭제**(CODE/QUIZ/QUESTION/SESSION/PLAYER/ANSWER/CONN + S3 이미지). 복구 불가. 안전장치로 Code 재확인 필요. |
| M-5 | 데이터 초기화 | 해당 Code의 **참여 데이터만 리셋**: PLAYER/ANSWER/CONN 삭제 + SESSION→`WAITING`. **QUIZ(메타)/QUESTION(문제·정답·이미지)은 유지**. 재플레이 및 관리자 테스트 후 리셋 용도. 안전장치로 확인 필요. |

> M-4(삭제)와 M-5(초기화)의 차이: 삭제는 퀴즈 자체를 없앤다. 초기화는 **문제는 그대로 두고 참가자/점수/진행만 비워** 처음부터 다시 플레이할 수 있게 한다.

### 3.2 퀴즈 관리자 (Host)

| ID | 기능 | 상세 |
|----|------|------|
| H-1 | Code로 세팅 진입 | 발급받은 Code + PIN으로 퀴즈 편집 화면 진입. |
| H-2 | 객관식 출제 | 단일 선택(single) / 복수 선택(multi) 지원. 보기 N개, 정답 1개 이상. |
| H-3 | 주관식 출제 | 텍스트 정답. **유사 정답 인정** (정규화 + 편집거리 임계값 + 허용 답안 목록). |
| H-4 | 이미지 첨부 | 퀴즈(문제)당 이미지 **최대 1개**. S3 업로드. |
| H-5 | Timeout 설정 | 퀴즈 **전체 공통** 문제당 제한시간(초) 설정. |
| H-6 | 인쇄용 출력 | 완성된 전체 문제 + 정답 체크 상태를 브라우저 인쇄(PDF 저장 포함)로 출력. |
| H-7 | 상품 당첨 인원 설정 | 2등~n등 랜덤 추첨 인원수(n) 설정. 1등은 기본 확정. |
| H-8 | 퀴즈 시작 제어 | 참여자 대기 화면에서 "시작" 트리거. |
| H-9 | 다음 문제 제어 | 문제별 리더보드 화면에서 "다음 문제" 트리거. |
| H-10 | 종료 및 최종 결과 | 마지막 문제 후 최종 순위 + 상품 추첨 결과 확정·브로드캐스트. |

### 3.3 참여자 (Player)

| ID | 기능 | 상세 |
|----|------|------|
| P-1 | 입장 | 참여 Code + 닉네임 입력 후 대기 화면 진입. |
| P-2 | 대기 | 관리자가 시작할 때까지 대기 화면 표시. |
| P-3 | 응답 | 현재 문제에 제한시간 내 응답. 응답 시각은 서버 기준으로 측정. |
| P-4 | 문제별 리더보드 확인 | 각 문제 종료 후 정답자 우선, 풀이시간(소수점 2자리 초) 순 리더보드. |
| P-5 | 최종 결과 확인 | 점수 높은 순 최종 순위 + 상품 당첨 여부. |

## 4. 상세 기능 명세 (사용자 지정 디테일)

### D-1. 자동 데이터 만료 (비용 최적화)
- 마스터가 지정한 만료일을 DynamoDB **TTL 속성**(Unix epoch, seconds)에 저장.
- 해당 시각 경과 후 DynamoDB가 자동 삭제(쓰기 비용 0). **삭제는 수 일 지연될 수 있으므로** 조회 시 filter expression으로 만료 항목을 제외한다.
- S3 이미지는 **S3 Lifecycle 정책**(만료일 + 버퍼) 또는 DynamoDB Streams(TTL 삭제 이벤트) → Lambda 연동으로 제거.

### D-2. 참여 대기 → 시작
- 참여자는 입장 직후 "대기 중" 화면을 본다.
- 관리자 화면에는 현재 참여자 목록과 **시작 버튼**이 보인다.
- 관리자가 시작하면 WebSocket으로 전체 참여자에게 첫 문제를 push → 화면 전환.

### D-3. 문제별 리더보드
- 문제가 종료되면(전원 응답 or timeout) 해당 문제의 리더보드를 산출.
- 정렬 우선순위: ① 정답자 우선 → ② 풀이시간 짧은 순.
- 풀이시간은 **소수점 2자리 초**까지 표기 (예: `3.47s`).

### D-4. 다음 문제 제어
- 문제별 리더보드 화면에서 관리자에게 **다음 문제 버튼** 제공.
- 클릭 시 다음 문제를 전체에게 push. 마지막 문제면 "결과 보기"로 대체.

### D-5. 최종 순위
- 모든 문제 종료 후 누적 점수 내림차순으로 1등부터 전체 순위 산출.
- 동점 처리: 누적 풀이시간이 짧은 참여자 우선 (tie-breaker).

### D-6. 상품 랜덤 추첨
- **1등은 기본 당첨** (확정).
- 관리자가 설정한 당첨 인원 n에 따라, **2등 이하 참여자 중 랜덤으로 (n-1)명** 추첨.
- 추첨 결과는 리더보드에 자동 표시되고 전체에게 브로드캐스트.
- 추첨은 서버(Lambda)에서 수행하여 공정성·재현불가성 확보.

### D-7. 마스터 발행/삭제/초기화 상세
- **발행 + 링크(M-1)**: 발행 시 서버가 참여자 링크(`/play?code=...`)와 호스트 링크(`/host?code=...`)를 생성해 반환. 호스트 PIN은 링크에 포함하지 않고 발급 응답/마스터 콘솔에만 1회 표시 → 마스터가 URL+PIN을 호스트에게 전달.
- **삭제(M-4)**: 해당 Code의 전 엔티티(CODE/QUIZ/QUESTION/SESSION/PLAYER/ANSWER/CONN)와 S3 이미지를 제거. 되돌릴 수 없음.
  - 안전장치: **UI에서 Code 재입력(confirm)** 후에만 실행. API도 `confirm`에 Code 일치 요구.
- **초기화(M-5)**: PLAYER/ANSWER/CONN 삭제 + SESSION→`WAITING`. QUIZ/QUESTION 유지.
  - 안전장치: **UI confirm**. 진행 중(`RUNNING`) 세션이면 경고 표시(강제 시 `force` 플래그 필요).
  - 초기화 후 호스트는 동일 문제로 즉시 재시작 가능, 참여자는 다시 입장.

## 5. 화면·디바이스 UI 요구사항

퀴즈는 **대형 스크린(공유 화면)에 문제를 띄우고, 참여자는 자기 기기로 응답만** 하는 Kahoot류 방식으로 진행한다. 화면은 디바이스가 아니라 **역할(role)** 로 분리한다.

### U-1. Host 화면 (대형 스크린 / 프로젝터)
- 현재 문제의 **본문 + 보기 텍스트 전부** 표시 (예: `A. Lambda`, `B. EC2` ...).
- 타이머(timeout 카운트다운), 응답 현황(응답 n/전체), 진행 제어 버튼(시작/다음).
- 문제별 리더보드, 최종 순위, 상품 당첨 결과 표시.
- 보통 Host가 PC/프로젝터로 띄우는 화면.

### U-2. Player 화면 (참여자, 디바이스 무관 — 모바일/PC 동일)
- **응답 전용 컨트롤러**. 문제 본문·보기 텍스트를 **표시하지 않는다** (문제는 대형 스크린 담당).
- 객관식: **보기 라벨(색상+문자) 버튼만** 표시 (`A`/`B`/`C`/`D` …). 대형 스크린의 보기 번호/색상과 1:1 매칭.
  - **단일 선택(SINGLE)**: 라벨 탭 → **즉시 제출** (반응속도 측정에 유리).
  - **복수 선택(MULTI)**: 라벨 여러 개 토글 선택 → **"제출" 버튼**으로 확정.
- 주관식(TEXT): **텍스트 입력창 + 제출 버튼**만 (문제 본문 비표시).
- 공통: 남은 시간 인디케이터, 제출 완료 상태, 대기/리더보드/결과 상태 뷰.
- 반응형: 화면 크기에 따라 버튼 크기·레이아웃 조정(모바일 우선, PC도 동일 컨트롤러).

### U-3. 라벨 매칭 규칙
- 보기 라벨/색상은 Host 화면과 Player 화면이 **동일한 순서·색상**을 공유해야 한다.
- 보기 색상 팔레트는 고정(예: A=빨강, B=파랑, C=노랑, D=초록)하여 참여자가 대형 스크린을 보고 자기 기기에서 같은 색 버튼을 누르면 된다.
- 따라서 Player에게 전달하는 데이터는 **보기 텍스트 없이 보기 id/라벨/색상·개수**만 포함한다(정답·본문·보기 텍스트 제외).

## 6. 비기능 요구사항

| 항목 | 요구 |
|------|------|
| 비용 | 사용량 기반(서버리스), 유휴 비용 최소화, TTL 자동 정리 |
| 실시간성 | 문제 전환/리더보드 갱신 지연 체감상 1초 이내 |
| 신뢰성 | 풀이시간·정답 판정은 서버 기준(클라이언트 조작 방지) |
| 확장성 | 다수 동시 세션(각 수십 명) 지원 |
| 보안 | 참여 Code는 입장용, 관리자 PIN은 편집·진행 제어용으로 분리 |
| 마스터 보안 | 마스터 콘솔은 참여자/호스트와 **별도 CloudFront 도메인으로 격리**. 마스터 API는 `X-Master-Key` 헤더를 **Lambda Authorizer**가 **SSM Parameter Store SecureString**과 검증(timing-safe). **CORS는 보조이며 보안 경계가 아님** |
| 접근성 | 인쇄 레이아웃 포함 WCAG 준수 지향. 색상 라벨에 문자 병기(색맹 대응) |

## 7. 범위 외 (초기 제외)
- 참여자 영구 계정/소셜 로그인
- 서버사이드 PDF 렌더링 (브라우저 인쇄로 대체)
- 다국어, 결제, 실제 상품 배송 연동
- 마스터 전용 별도 AWS 계정 격리(현 규모엔 과도 — 별도 CloudFront + Authorizer로 충분)
